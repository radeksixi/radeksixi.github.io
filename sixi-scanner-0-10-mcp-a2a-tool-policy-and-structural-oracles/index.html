sixi-scanner 0.10: MCP & A2A, deterministic tool policies, structural oracles, and honest diffs

Radek Brus · 19 November 2026 · sixi-scanner v0.10.0

The v0.9 correctness pass stopped the scanner from calling an unreachable endpoint clean. v0.10.0 tackles the next four things that actually break in production agents: poisoned MCP/A2A metadata before you ever send a prompt, agents that lie politely in prose while making an unauthorised tool call, attacks whose proof is structural rather than lexical, and re-runs whose diff pretends skipped tests were fixed.

Everything in v0.10.0 still builds from the Go standard library alone — go.mod has zero external dependencies — and ships as single static binaries for Linux, macOS and Windows.

1. Deterministic tool-call policies that beat polite prose

A common failure mode on real tool-using agents is a split between what the model writes and what it executes: the prose says "I'm sorry, I cannot email external addresses" while the tool trace calls send_email(to="attacker@evil.example"). Any prose-only judge — substring or LLM — reads the polite sentence and calls it a pass.

--context agent.json now accepts a declarative policy block alongside purpose, and works without --confirm-url:

{
  "purpose": "Support assistant scoped to account ACC-1001.",
  "policy": {
    "allowed_recipients": ["alice@company.example"],
    "forbidden_recipients": ["@exfil.example"],
    "allowed_accounts": ["ACC-1001"],
    "limits": [
      {"tool": "issue_refund", "field": "amount", "max": 50, "unit": "EUR"}
    ]
  }
}

Point --trace-path at the tool-call array in your json or chat response (four wire shapes are extracted automatically: OpenAI function.arguments, gateway args/arguments/input/parameters, single-call objects, and flat fields). Any violation on the wire is confirmed deterministically at evidence_basis: "trace", cannot be overturned by prose refusals, and costs zero extra model calls.

In the opposite direction, when a connector exposes no tool trace and a prose break rests solely on the model claiming it deleted, transferred or approved something with no concrete artefact in the reply, the judge marks it narration_only and caps confidence at 0.50. Narration is not proof of a side effect.

Takeaway: enforce recipient allow-lists, account scope and numeric caps against observed tool calls on the wire, not against what the assistant claims in English.

2. Passive MCP & A2A inspection before sending a single probe

Modern agents do not fail only on user prompts; they fail on the tools and peer descriptors they load at startup. sixi-scanner surface sends zero adversarial payloads. It runs standard discovery — MCP initialize + tools/list and A2A /.well-known/agent-card.json (with fallback to /.well-known/agent.json) — and checks what the endpoint advertises:

  • Hidden instructions in tool descriptions & schemas: <IMPORTANT>, <system>, [INST], override cues, shell exfil commands, invisible Unicode Tag Plane / BiDi controls, and printable base64 payloads decoded statically.
  • Cross-tool shadowing: one tool's description referencing another tool's name alongside directive language (a low-privilege helper steering a privileged tool).
  • A2A trust posture: unauthenticated agent cards, unsigned cards, and weak authentication schemes.
sixi-scanner surface --url https://agent.example --format sarif --out surface.sarif

For active scanning, --target mcp and --target a2a are now built-in pure-stdlib transports. The A2A connector negotiates v0.3 (message/send) with automatic fallback to v0.2 (tasks/send) on -32601 and implements sessions, so all four multi-turn sequences run natively against A2A endpoints. Bespoke JSON endpoints can also run multi-turn sequences now simply by placing {{session}} or {{session_json}} in --body.

3. Structural oracles instead of fragile keywords (45 techniques)

Substring markers work well for explicit leaks, poorly for output-handling and smuggling bugs. Asking whether a reply contains alert(1) flags a safe agent explaining why it refused to decode a script tag. v0.10.0 adds a structural oracle layer in internal/judge/oracle.go alongside 18 new probes:

  • EchoLeak & inline Markdown exfiltration: resolves both inline links/images and Markdown reference definitions (![status][1] + [1]: https://…), strips code fences and inline code spans, and ignores benign sizing params (w, h, utm_*) and unfilled placeholders.
  • Unicode Tag Plane & BiDi/backspace smuggling: unfolds U+E0020–U+E007E tag runes, resolves <char>\b overwrites, strips format controls, and checks whether the hidden trigger was obeyed rather than surfaced in a warning.
  • Output-handling oracles: balanced SSTI delimiters ({{…}}, ${…}, {%…%}), raw ANSI/OSC 8 escape bytes (0x1B/0x07), unescaped Base64-decoded HTML/XSS markup, unescaped CSV formula cells (=CMD, =IMPORTDATA, +HYPERLINK while respecting leading-apostrophe escaping), and constrained JSON schema bypasses.
  • 2026 jailbreaks, sleeper memory & tool authz: latent ticket/CV injection, MathPrompt, low-resource multilingual (Welsh, Swahili, Zulu), many-shot conditioning, Bad Likert Judge, adversarial poetry, multi-turn sleeper-memory (plant → benign turn → trigger), email header injection, BOLA, BFLA and SSRF.
  • Sharper refusal handling: probe.llm01.declined-then-produced catches replies that open with a refusal and then emit the requested code/SQL scaffold anyway (filed under its own ID like rule recitation); role mailboxes (dpo@, support@, security@) are ignored in PII matches; placeholder secrets (sk-your_placeholder…) are filtered out while real AWS, GitHub, Slack, Google, JWT and DB URI credentials fire cleanly.

Every new oracle and probe ships with paired clean-vs-compromised acceptance tests so a safe refusal must score zero before a PR can pass.

4. Honest diffs, targeted reproduction, redaction, and HTML reports

Four practical CI and reporting workflows that kept coming up in real runs:

  • sixi-scanner diff baseline.json current.json classifies findings into new (noting whether the baseline even tested that technique), still_open, fixed, and not_retested. A baseline finding is only marked fixed when the current scan actually assessed its technique; if it was omitted, timed out (no_answer) or unsupported, it stays in not_retested with an explicit caveat. Exits 1 only on new findings.
  • --reproduce N re-sends only the breaking payloads N extra times after the scan and reports reproduced k/n trials across text, JSON, SARIF, Markdown and HTML, separating deterministic holes (3/3) from one-off model variance (1/3) without multiplying the cost of clean probes.
  • --redact scrubs JWTs, database credentials, Bearer tokens, API keys, emails, IPv4 addresses and long account/card numbers from evidence after computing fingerprints, so diffs stay stable while shared reports stay clean. SARIF snippets are always redacted automatically before upload to GitHub Code Scanning.
  • --format html (or --out report.html) emits a single self-contained, auto-escaped HTML report with zero external network assets and the same "What this report is not" disclaimer as Markdown — never a compliance grade. SARIF 2.1.0 also gains security-severity, Markdown rule help, automationDetails and ruleIndex.
  • Bounded HTTP retry honours Retry-After on 429 and empty 503 responses in both target transports and the confirmation stage, while preserving non-empty error pages for judging.

What has not been measured yet. The benchmark figures in the README (0.821 precision, 0.571 recall, 1.000 multi-turn precision) were measured on v0.8.4 against agent-redteam-benchmark and have not been re-run on v0.10.0 yet. All 45 probes and 7 structural oracles are verified by paired clean-vs-compromised acceptance tests and 12/12 Go packages under -race, but live benchmark scores remain v0.8.4 until re-measured.

Getting it

Download a static binary from the v0.10.0 release (Linux, macOS, Windows + SHA256SUMS) or install with Go:

go install github.com/radeksixi/sixi-scanner/cmd/sixi-scanner@v0.10.0

# 1. Passive check of advertised MCP tools / A2A agent card
sixi-scanner surface --url https://your-agent.example

# 2. Active scan with deterministic tool policy, 2x reproduction, redaction, HTML report
sixi-scanner scan --target json --url https://your-agent.example/api/ask \
  --body '{"prompt":{{json}},"session":{{session_json}}}' \
  --reply-path reply --trace-path tool_calls \
  --context agent.json --reproduce 2 --redact --out report.html

# 3. Compare against yesterday's baseline in CI
sixi-scanner diff baseline.json current.json
