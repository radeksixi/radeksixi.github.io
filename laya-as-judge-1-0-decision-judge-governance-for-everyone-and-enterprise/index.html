laya-as-judge 1.0: one open-source Decision, Judge & Governance API built for everyone — and ready for regulated enterprise

Radek Brus · 22 November 2026 · laya-as-judge v1.0.0 · Sixi Assure

AI evaluation and routing software usually breaks along an artificial divide. On one side sit lightweight local scripts that are fun to prototype with, but fail the moment a security architect asks for calibrated risk thresholds, deterministic deny rules, or a verifiable audit trail. On the other side sit closed enterprise guardrail clouds that require streaming proprietary customer state to third-party APIs, lock you into proprietary schemas, and charge per evaluation token until you quietly turn them off in production. Today I am releasing laya-as-judge v1.0.0 (Apache-2.0) — joining sixi-asi v1.0.0 and sixi-scanner v1.0.0 as the third stable pillar of Sixi Lab R&D — designed to work identically on a developer's single GPU and inside an air-gapped enterprise enclave.

One API, three operational modes — zero output tokens

Every production agent eventually needs three distinct capabilities: choosing an operational action, judging whether content or trajectories meet quality and safety rubrics, and deciding whether a proposed action is actually safe to commit. laya-as-judge v1.0.0 exposes all three through one Python SDK, one CLI (laya-judge), and one FastAPI HTTP server with zero autoregressive token decoding and zero JSON parse failures:

Mode HTTP Endpoint & Python Entry What It Solves Output Contract
1. Decision API POST /v1/decisions
POST /v1/systemone
SystemOneHTTPBackend		 Drop-in local replacement for cloud Decision APIs (Jev, Google, Azure) — ticket routing, tool calling, triage, classification with state/input and noul/bool wire compatibility. Strictly typed noul, choice, and score answers with calibrated simplex probabilities, 0 output tokens.
2. Judge API POST /v1/judge
FaithfulnessJudge, SafetyGuardJudge, CustomJudge		 Inline guardrails, RAG hallucination audits, pairwise A/B evaluation, agent trajectory checks, and offline batch/CI benchmark suites. passed, per-criterion typed judgements, Shannon-entropy confidence, Top-1 probability, and latency/cost telemetry.
3. Hybrid: The Judged Decision POST /v1/judged-decision
JudgedDecisionEngine		 Answers the real production question: "Not just what did the agent pick, but is it safe, grounded, and policy-compliant to execute?" Explicit 4-way ActionGate (commit / fallback / abstain / block), effective_decision, calibrated_risk, and step-by-step JSON audit_trace.

Why it works for individual developers, indie teams, and startups

Enterprise governance tools usually fail developers because they assume a Kubernetes cluster and a six-figure contract before your first request returns 200 OK. laya-as-judge v1.0.0 flips that equation:

  • Zero-friction start (0 GB VRAM): pip install 'laya-as-judge[server]' && laya-judge serve --profile emulator boots all three API modes in under a second with zero model downloads for local integration tests and CI pipelines.
  • Runs on hardware you already own ($0.00/month): Built-in hardware profiles match real VRAM envelopes — edge-6gb (5.88 GB VRAM, fits NVIDIA Jetson Orin Nano 8 GB or an RTX 4060 8 GB, 88 ms P50), rtx-16gb (11.75 GB VRAM on one RTX 4060 Ti / 5060 Ti / 5070 Ti 16 GB, 78.0% 6-benchmark average, 12/12 red-team catch rate, 100% Polish accuracy, 3.3× faster multi-question log analysis), and rtx-16gb-glide (11.11 GB, 78.7% 6-benchmark average, 92.5% When2Call, 0.0287 calibrated Top-1 ECE).
  • No cloud lock-in — upgrade only when you want multimodality: Because the Decision API uses standard /v1/decisions and /v1/systemone wire schemas, you can start 100% local at $0.00 and turn on Laya-Omega whenever you need raw vision, audio, or video (11/11 wins over Gemini Decision 1 across 2,250 questions, pooled 0.0234 ECE, $0.77 total).

Why regulated enterprises can deploy it without compromises

In banking, insurance, healthcare, pharmaceuticals, public administration, and industrial OT, the blocker is rarely model intelligence — it is control, auditability, data residency, and predictable failure behavior. Every piece of v1.0.0 was built from live red-teaming experience and aligns directly with Sixi Assure:

  1. 100% air-gapped & data-sovereign operation: With local GGUF decision servers (llama-server /v1/systemone) or on-prem PyTorch/MLX encoders, zero customer PII, medical abstracts, financial payloads, or internal tool schemas leave your network. That maps cleanly to GDPR/RODO residency rules and strict internal data-classification policies.
  2. Deterministic-first, fail-closed security gates: Neural models are probabilistic; compliance policies are not. In JudgedDecisionEngine, deterministic Python policy_rules (including the built-in spoofed_audit_guard_rule that stops fake [AUDIT_PASSED=TRUE] and [ADMIN_TOOL_OVERRIDE] injections) execute on every call regardless of audit policy. Even better: the default audit_policy="on_high_stakes" is fail-closed — if an operator forgets to declare high_stakes_actions, every action is audited instead of silently bypassing verification.
  3. Calibrated probabilities you can actually set SLAs on: Uncalibrated LLM confidence scores are unusable for risk thresholds. laya-as-judge v1.0.0 ships TemperatureScaler and out-of-fold MetaCalibrator (100% Top-1 invariant), proven live to cut 4-bit quantized ECE by 59% (0.0701 → 0.0287) and reach 0.0234 across 2,250 hybrid questions. Risk officers can set concrete thresholds (min_top1_prob, min_margin, max_judge_risk_score) and prove their selective accuracy via AURC and Acc@80%Cov.
  4. Four-way operational control & immutable audit traces: Rather than a brittle pass/fail boolean, /v1/judged-decision routes every action into COMMIT (autonomous execution), FALLBACK (safe pre-approved substitute such as request_more_info), ABSTAIN (human-in-the-loop review queue), or BLOCK (hard refuse). Every response carries a machine-readable JSON audit_trace recording which decider, cross-family verifier, orthogonal judge, and deterministic policy rule fired — directly supporting EU AI Act Article 12/14 logging & human oversight, DORA operational resilience evidence, and NIS2 incident forensics.
  5. Zero-dependency wire parity & Apache-2.0 licensing: No proprietary SaaS seat tax, no black-box prompt weights changing silently behind an endpoint, and reproducible offline benchmarks via laya-judge suite.

Five-minute deployment: from laptop to air-gapped server

# 1. Install laya-as-judge v1.0.0 with HTTP server extras
pip install 'laya-as-judge[server]'

# 2. Launch verified local Tier-1 (Kev-4B) + Tier-2 (Clef-Flash 9B joint-schema) in 11.75 GB VRAM
llama-server -hf ggml-org/Kev-4B-GGUF:Q4_K_M --port 8080 --ctx-size 8192 -b 2048 -ub 2048 --parallel 2
llama-server -hf ggml-org/Clef-Flash-GGUF:Q4_K_M --port 8081 --ctx-size 8192 -b 2048 -ub 2048 --parallel 2

# 3. Start the unified 3-mode Decision / Judge / Judged-Decision API (fail-closed default)
laya-judge serve --profile rtx-16gb \
  --tier1-url http://127.0.0.1:8080 \
  --tier2-url http://127.0.0.1:8081 \
  --port 8000

From there, any application — Python, Go, TypeScript, .NET, Java, or an API gateway — calls POST /v1/decisions for fast typed routing, POST /v1/judge for quality/safety scoring, or POST /v1/judged-decision for policy-gated autonomous execution.

Honest boundaries in v1.0.0

  • Local-only profiles are text-only by design: Local GGUF decision encoders do not process raw screenshots, audio clips, or video frames yet — for multimodal inputs, use OmegaDecisionEngine (hybrid cloud escalation) or convert media to structured text/DOM/ASR first.
  • Single-turn vs stateful cumulative business rules: /v1/judged-decision excels at per-decision grounding, injection defense, and stateless policy rules, while cumulative multi-turn session invariants (like two separate 30-EUR refunds beating a 50-EUR cap) should be enforced by stateful deterministic tool-policy middleware and tested continuously with sixi-scanner.
